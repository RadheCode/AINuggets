# Website Feature Summary

## Overview

The website is a responsive daily briefing experience. Its current identity and topic are configured in `product/`; it presents four or five curated stories in a single-screen, bento-style experience backed by an automated content-generation and publication platform.

## Reader-facing website features

| Feature | What it provides |
|---|---|
| Daily briefing | Presents a focused daily briefing of four or five selected stories, designed to reduce the need to follow an endless news feed. |
| About page | The header's About link opens a dedicated, responsive page that explains the product's focused five-story, under-two-minute daily briefing for busy readers. It retains the shared navigation, feedback, sign-in, color-mode controls, and visual language. |
| Responsive story grid | Displays stories as fixed, visually distinct tiles with lead and wide layouts. The layout adapts across desktop and mobile breakpoints. |
| Story detail dialog | Selecting a story opens an accessible modal with its category, title, summary, source link, and previous/next story navigation. A compact footer cue shows the keyboard shortcuts in clear words: Tab switches the summary level, Up and Down arrows scroll the content, and Left and Right arrows browse stories. |
| Configurable summary levels | The common product configuration enables Quick take, Overview, and Deep dive by default. Its UI and generation switches are independently configurable: the dialog dynamically renders only available enabled views, while future editions generate and persist only configured summary variants. Each context enforces its minimum character count; its configured maximum is an advisory concision target, so complete meaningful prose is never truncated or rejected for running long. |
| Client-side content caching | Caches the fetched edition (stories) in the current tab's session storage with a five-minute freshness window that mirrors the content API's own edge cache. Switching to the About page and back to Today within that window renders the story grid instantly from the local cache instead of refetching every story, avoiding a slow reload on each tab navigation. |
| Client-side session caching | Caches the last confirmed sign-in session (and its daily streak) in the current tab's session storage with a five-minute freshness window, keyed to the active session token. Returning to Today within that window restores the steak immediately instead of flashing "0" and re-fetching the session from the API; the cache is invalidated on sign-out or token change. |
| Static-asset caching policy | A Cloudflare Pages `_headers` manifest revalidates HTML and application code (server ETags return instant 304 responses) so freshly deployed code and published content always arrive, while company artwork is cached for a week to avoid re-downloading on every page switch. |
| Client-side visit deduplication | When returning to a page within a short window, only the first visit in any 30-second session window is reported to analytics; rapid Today/About toggling no longer issues a duplicate visit POST for what is effectively one reading session. |
| Source attribution | Each story detail view provides a safe external link to the original source, opening in a new tab with appropriate security attributes. |
| Edition preview by date | Supports `?date=YYYY-MM-DD` (optionally `?edition=N`) URL parameters so a reader or editor can load the appropriate published edition for a specified date and number, or the latest available edition. The main UI shows the latest edition by default; the dated/edition URL is a "hidden pill" for SEO/indexing and feed links. |
| Multi-edition per day | Supports multiple numbered editions per editorial day: every eligible generation run creates a new edition (edition #1 morning, #2 evening, etc.) and marks it latest; nothing is ever overwritten. The old same-day-refresh and edition-overwrite behavior was removed. Feed links point to numbered editions when `edition_number > 1`. |
| Atom RSS feed | Exposes `GET /feed.xml` on the content Worker serving an Atom feed of up to ten published editions for RSS/Atom readers and aggregators, with each entry linked to its edition URL (`/?date=YYYY-MM-DD&edition=N` when the edition number is greater than 1, otherwise `/?date=YYYY-MM-DD`) and listing its story titles with safe source attribution. The feed is public and cacheable. |
| SEO discoverability assets | Serves `robots.txt` and `sitemap.xml` from the Pages root for search-engine crawling, plus a branded SVG favicon, an Open Graph share image, and matching social meta tags (`og:image`, `twitter:image`) so shared links and shared editions render attractively on social platforms. |
| Feed and entity artwork matching | Resolves each configured feed to local publisher or editorial-category artwork before falling back to configured entity references in story text. The feed configuration test requires every approved feed to have a valid local artwork mapping. |
| Light and dark modes | Provides a color-mode toggle, respects the operating-system preference when no choice has been saved, and remembers the reader's choice in browser storage. |
| Theme system | Loads the active visual theme from centralized configuration, allowing the site presentation to change without changing content retrieval or behavior. |
| Product configuration boundary | Keeps product identity, editorial framing copy, public API endpoints, browser storage namespace, public OAuth settings, and product-specific artwork matching together in the root `product/` folder so the site can be retargeted without changing shared behavior or themes. |
| One-prompt product rebranding | Provides a repository-local skill that converts the configured product to a new editorial domain, validates remaining references, and clearly identifies the external provider, OAuth, deployment, and editorial-data actions that still require user approval. |
| Google sign-in | Supports Google-only OAuth/OpenID Connect sign-in through Google Identity Services. A conventional header Login button opens a compact sign-in popover with a clear heading and full-width Google action, which activates Google's account chooser rather than relying on a silently suppressible One Tap prompt. The Worker verifies each credential, creates or updates a D1 user profile, and issues an opaque 30-day session token so the signed-in state survives refresh. The signed-in header shows the account menu and application sign-out control; the sign-in control is hidden when Google configuration is unavailable. |
| Configurable daily reading streak | Shows every reader an animated Flame control with its visible streak count and label, sized to the color-mode button's height. Signed-out readers activate it to open the existing sign-in popover. A hover or keyboard-focus floating guidance bubble calmly explains the product-configured visit flexibility without changing the control's layout. A verified sign-in or an authenticated published-edition request qualifies once per UTC day; the product-owned maximum-gap setting controls how many UTC days may separate qualifying activities while continuing the streak. The Worker calculates and persists current and longest streaks, so the browser cannot alter them. |
| Streak celebration | Fires a self-contained canvas-confetti and glassmorphic toast celebration when a signed-in reader's streak increases to a milestone value: streak 1 (start), every 3rd day (milestone), or every multiple of 5 (mega, escalating at 20+). The engine in `content-engine/celebration.js` emits themed confetti particles, sparkle stars, expanding rings, a pill-glow pulse, and a top-edge shimmer; it respects `prefers-reduced-motion` by showing only the toast. Copy and emoji are product-owned through `product/config.js` and the toast reuses the shared dialog elevation language. |
| Reader feedback | Provides an attached Edge tab that opens an accessible soft-rounded feedback dialog with a required email address, a whole-star rating from 1 through 5, feedback message, acknowledgement, and D1-backed submission. Signed-in readers see their verified email prefilled and locked; anonymous readers can enter their own email. |
| Story share | The story detail dialog's Share action shares the current dated/edition URL through the native Web Share API when available, falling back to copying the link to the clipboard with a brief "Link copied" confirmation, and finally to an email link. Shared links carry the viewer's focused edition (`?date=…&edition=…`), so each shared post points at an indexable dated page rather than the generic homepage. |
| Newsletter subscribe | An attached blue Edge tab opens an accessible dialog where readers can subscribe with their email to the daily-briefing newsletter. Submission posts to `POST /api/subscribe`, is validated server-side, and writes to the private D1 `subscribers` table (one row per email, deduplicated; signed-in readers link their verified profile email). The dialog confirms success, notes a duplicate subscription, and shows a calm error on failure; the control sits alongside Feedback in the shared Edge tab group. |
| RSS feed promotion | Alongside the Feedback and Subscribe Edge tabs, an "Subscribe via RSS" link points at the content Worker's public `GET /feed.xml` Atom feed so feed readers and aggregators can subscribe directly. The URL is resolved at runtime from the same environment-aware API base that powers the public content API, so it always points at the active beta or production Worker. |
| Reader support (donation) | Provides a discreet "Support" pill hosted in the site footer's right side that opens an accessible, larger two-pane dialog with a heart brand mark and a one-time contribution description. A left rail stacks small provider icon tiles (original premium SVG marks for Ko-fi and Razorpay) one over the other with the configured default pre-selected; the right pane shows the selected provider's name, tagline, details, and a full-width checkout button that opens the provider's hosted checkout in a new tab. Each provider is a hosted URL (Ko-fi, Razorpay Payment Links, PayPal.me, Cashfree/PayU links, Buy Me a Coffee), so no backend or processor SDK is needed. Without providers the dialog presents a calm "support coming soon" state, so the shared shell ships without hard-coding provider identifiers. All copy (label, title, description, provider prompt, new-tab hint, and coming-soon text) resolves from `product/config.js` edges. |
| Reader feedback table | Provides a repository-local, read-only operator skill that exports every selected beta or production reader-feedback record as a private Markdown table with email, rating, message, and explicitly labeled IST submission time. |
| Privacy-minimal visitor analytics | Records one best-effort first-party page visit when a public page loads using an opaque browser identifier stored only as a one-way hash, an edge-derived country code and readable English country name, and a server timestamp. A private operator report provides current IST day, Monday-based week, and month totals for unique visitors, unique countries, and page visits. It does not retain IP addresses, precise locations, referrers, browser fingerprints, user-agent strings, or authenticated-profile links; raw events expire after 90 days. |
| Accessible interactions | Uses semantic navigation and controls, descriptive labels, feedback status updates, modal dialogs, keyboard summary switching (Tab) and scrolling (Up/Down arrows), and keyboard story navigation (Left/Right arrows) with a visible dialog-footer cue. |

## Content and publishing platform

| Feature | What it provides |
|---|---|
| Cloudflare D1 content store | Stores numbered dated editions (per `edition_date` + `edition_number` with an `is_latest` flag), ordered stories, publication status, source metadata, and generation-run audit records in a dedicated database. |
| Public content API | Serves only published editions through latest-edition, date-specific, and date+edition-number endpoints, with health reporting, edge-cacheable responses, and configured browser-origin restrictions. |
| Twice-daily scheduled generation | Runs a scheduler-neutral job at 6:30 AM and 6:30 PM IST (01:00 and 13:00 UTC), creating edition #1 (morning) and edition #2 (evening). It can be invoked by Cloudflare Cron, GitHub Actions, container schedulers, or operating-system cron. Every eligible run creates a new numbered edition; editions are never refreshed or overwritten. |
| RSS/Atom source collection | Collects recent articles from an editable approved feed list, with a custom HTTPS JSON candidate source available as an optional replacement. |
| Candidate selection | Normalizes URLs, removes duplicates, excludes canonical URLs used by published editions in the ten editorial days before the target date (`D - 10 <= edition_date < D`; same-day editions are not excluded), and prefers category diversity when selecting exactly five candidates. Product editorial configuration switches the built-in collector between priority-and-freshness ranking and randomized candidate ordering without removing per-feed priority values; fewer than five eligible candidates fails before model generation. |
| Provider-powered summarization | Produces structured original summaries for the product-configured generated detail levels through pluggable summary providers tried in the product-owned `fallbackOrder`: an OpenAI-compatible Chat Completions provider, OpenRouter.ai, and the free Cloudflare Workers AI binding (`env.AI`). The first provider that succeeds wins. |
| Provider fallback chain | Wraps multiple summary providers in a composite with automatic fallback. Each provider kind supports internal model-level fallback (array of models). On retryable errors (404, 500, 502, 503, 504 for OpenAI-compatible; 429, 5xx, rate/capacity terms for Workers AI), falls through to the next model or provider. Request timeout is 300 seconds per model call. |
| Model analytics | Provides a repository-local, read-only operator report of per-model aggregate statistics (attempts, successes, failures, response sizes), model usage by date, run-level summaries with durations, validation retry analysis, and per-run model progression showing which model was tried and the fallback chain followed. |
| Content validation | Rejects invalid editions before storage by enforcing date, story count, unique IDs and positions, required fields, supported layouts and artwork, mandatory summary minimums and formats, and HTTPS URLs. Summary maximums guide generation without rejecting complete summaries that exceed them. |
| Publishing workflow | Publishes valid editions automatically by default, with a configuration option to save future editions as drafts for editorial review before publication. |
| Detailed generation-run investigations | Gives each attempt a correlated UUID and records ordered, safe source, selection, generation, validation, persistence, and terminal decision events. A protected internal endpoint and unified D1 query show the complete timeline for one run with explicitly labeled IST timestamps; beta supports a non-persisting dry run. Completed run data is retained for three days. |
| Multi-edition persistence and audits | Every eligible generation run creates a new numbered edition and marks it latest; an existing edition never causes a skip or an overwrite. The prior latest edition for a date is flipped to `is_latest=0` when a new numbered edition is saved, and each generation attempt is recorded as started, skipped, succeeded, or failed. The same-day-refresh and edition-overwrite (`forceReplace`) features were removed. |
| Failure protection | Keeps the most recent valid published edition available if content collection, generation, validation, or persistence fails; incomplete or fabricated editions are not published. |
| Portable architecture | Separates the generation core from Cloudflare-specific code so source, model, scheduler, and infrastructure adapters can be replaced without rewriting the core workflow. |

## Operational and safety capabilities

| Feature | What it provides |
|---|---|
| Secret-safe configuration | Keeps model API keys and operational tokens out of browser assets, logs, and source control; runtime adapters receive them from secret stores. |
| Provider configuration checks | Detects missing or incomplete model settings explicitly and records a safe skipped run rather than attempting to generate content with partial configuration. |
| Bounded external requests | Uses request timeouts for feeds, custom sources, and the summary provider to limit stalled integrations. |
| Untrusted-source handling | Treats article and feed content as untrusted input and does not execute instructions contained in source material. |
| Copyright-aware storage | Stores original summaries and source attribution rather than raw copyrighted article text. |
| Isolated beta deployment | Uses an independent beta Pages project, Worker, D1 database, Cron trigger, and Worker secrets at `https://beta-ai-nuggets.pages.dev`, preserving production data and traffic. |
| Protected production deployment | Defaults all deployment and secret-sync scripts to beta. Production at `https://ai-nuggets.pages.dev` requires an explicit environment and confirmation switch, preventing accidental production releases. |
| Beta parity gate | Requires beta to receive and validate every application and infrastructure change before a production release. A guarded editorial sync copies only published editions and stories into beta, preserving the isolation of reader data and operational history. |
| Cloudflare deployment support | Includes deployment scripts and infrastructure configuration for Cloudflare Pages, the content Worker, D1 migrations, Worker secrets, and Cron registration. |
| Generation-run analytics | Provides a repository-local, read-only operator report of the twice-daily content automation: Day / Week / Month IST summaries of runs count, succeeded / failed / skipped counts, success rate, and the latest retained run with its status and safe failure reason. Counts include only retained runs (three-day retention). Model/provider analytics are available as a separate companion report. |
| Published-content summary | Provides a repository-local, read-only operator report of editions status totals, stories by category, total published stories, and recent editions over the last 7 days. |
| Combined analytics skill | Provides a repository-local, read-only "fetch-analytics" skill that runs visitor analytics, generation-run analytics, model/provider analytics, reader feedback, and the content summary together for a chosen beta/production/both environment, keeping each environment's totals separate and all timestamps labeled IST. |

Google sign-in creates or updates a D1 profile containing the verified Google subject, email, display name, optional picture URL, and server-managed activity data. Browser storage contains only an opaque bearer session token; D1 stores only its SHA-256 hash. Authenticated published-edition requests refresh the profile activity and can record one qualifying daily streak activity; the browser never sends a date or streak value. Sessions expire after 30 days.
